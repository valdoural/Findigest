# Финансовый дайджест — архитектура настольной версии

## Принцип

Отчёт (6 листов) переносится **без изменения разметки, размеров и логики**. Всё, что в веб-версии
давала облачная среда (`window.claude.use(...)`: база, ИИ, сохранение файлов), подменяется локальными
модулями через мост `bridge.js`. Правки исходной страницы — только в `scripts/prepare-digest.js`
и каждая проверяется (если шаблон не найден, скрипт падает).

```
┌──────────────────────────── Окно (renderer, без доступа к Node) ────────────────────────────┐
│ digest/index.html  — отчёт 1:1           desktop/connections.js — панель «Подключения»       │
│ desktop/bridge.js  — window.claude.use() → fdNative                                         │
│ wizard/index.html  — мастер первой настройки                                                │
└───────────────────────────────▲─────────────────────────────────────────────────────────────┘
                                │ preload.js: window.fdNative (белый список вызовов)
┌───────────────────────────────┴──────── Основной процесс (main) ────────────────────────────┐
│ ipc.js  — каналы store:* dl:* ai:* conn:* app:*                                             │
│ config/settings.js — settings.json        config/secrets.js — secrets.json (DPAPI)          │
│ db/database.js + migrations/*.sql — SQLite с автомиграциями      db/store.js — таблицы      │
│ ai/router.js → providers/{anthropic,gemini,openai}.js  (основной + запасные)                │
│ connectors/{zenmoney,mail}.js   digest/build.js — расчёт листов   digest/service.js — обновление│
│ scheduler.js — расписание, трей и автозапуск — в main.js                                    │
└─────────────────────────────────────────────────────────────────────────────────────────────┘
```

## Данные пользователя (`%APPDATA%\FinDigest\`)

| Путь | Что | Особенности |
|---|---|---|
| `config\settings.json` | настройки | без секретов; недостающие поля подставляются из `DEFAULTS` |
| `config\secrets.json` | ключи ИИ, токен Zenmoney, пароль почты | отдельный файл, `enc:` = зашифровано Windows; можно вписать ключ вручную — зашифруется при запуске |
| `data\digest.db` | SQLite | создаётся сам, схема обновляется миграциями |
| `files\archive\<id>\` | оригиналы фото/PDF | в БД только ссылки |
| `logs\` | журнал | секреты маскируются |

### Таблицы БД
`docs` (состояние отчёта, совместимо с веб-версией) · `archive` + `archive_files` (чеки и квитанции)
· `receipt_items`, `bill_items` (нормализованные позиции для аналитики и запросов ИИ) · `sync_log` · `meta`.

## Данные Zenmoney (этап 2)

`connectors/zenmoney.js` забирает `/v8/diff`: первый раз всю историю, дальше только изменения (метка сервера в `meta.zm_server_ts`), удалённые операции удаляются.
`digest/build.js` считает из `zm_*` те же наборы, что были «зашиты» в веб-версию (`TX`, `HIST`, `MON`, `AC`, `KL/FM/MM`, `UT` …), отчёт берёт их вместо констант (`FDD.X ?? <значение снимка>`).

Правила сверены с отчётом Zenmoney на всей истории (`test/compare-web.js`):

| Набор | Правило | Сверка |
|---|---|---|
| MON — доход/расход по месяцам | операции «доход/расход» по счетам в балансе, без переводов | 30 из 32 мес. до рубля; 12.2025 и 10.2026 — данные изменились после снимка |
| HIST — категории за 3 мес. | факт по категории, без «Корректировки» и операций без категории | совпадает; добавлены «Дом, уют» и «Кошка», которых не было в списке веб-версии |
| SEP / PY — дни прошлого месяца / года | все расходы / без «Корректировки» | до копейки |
| MS — разовые крупные | операции от 100 000 ₽ | совпадает |
| UT — ЖКХ по месяцам | категория «Коммуналка» | совпадает (31 мес.) |
| FM / MM — капитал и ипотека | стартовый остаток + операции; валютные счета — с первой операции | ипотека точно; капитал ±9 тыс. (курс USD текущий, а не на дату) |
| Y_PREV / Y_CUR — сравнение лет | без «Корректировки» и операций без категории | правило применяется ко всем месяцам (в веб-версии — вручную к двум) |

## Чеки из почты (этап 3)

`connectors/mail.js` ищет по IMAP письма от адресов из «Подключения → Почта» (адрес без @ — часть адреса, `ofd` = любой ОФД)
и, если включено, по теме («кассовый чек», «электронный чек»). Если сервер не ищет по русским словам, тема проверяется в программе.
`connectors/mail-extract.js` превращает письмо в записи архива в формате отчёта:

| Что в письме | Что попадает в архив |
|---|---|
| PDF с текстом | текст чека + первая страница картинкой |
| PDF-скан | картинки страниц (читает ИИ) |
| фото во вложении | картинка (логотипы < 15 КБ и встроенные картинки пропускаются) |
| HTML/текст письма | текст, если похоже на чек (слова «итог», «ФН», «кассовый чек»… и суммы) |

Каждое письмо обрабатывается один раз (`mail_seen`, по Message-ID). Письма в почте не меняются и не помечаются прочитанными.
Новые чеки разбирает сам отчёт — той же кнопкой «Разобрать» и теми же подсказками ИИ (`fd_autoparse` после перезагрузки).
Если дата не найдена в чеке, берётся дата письма. Проверка — `test/mail-test.js` (тестовый IMAP-сервер, 7 писем).

## Помощник (этап 4)

Кнопка с микрофоном в шапке (`desktop/assistant.js`) или **Ctrl+Shift+Пробел** из любой программы — окно откроется и начнёт слушать.

1. **Запись** — микрофон → WAV 16 кГц моно прямо в окне; запись останавливается сама, когда вы замолчали (1,4 с тишины), максимум 30 с.
2. **Распознавание** — `ai/router.transcribe`: Gemini (аудио внутри запроса) или GPT (`gpt-4o-mini-transcribe` / `whisper-1`).
   Claude речь не распознаёт — с одним ключом Claude помощник работает текстом.
3. **Ответ** — `assistant/assistant.js`, два шага: ИИ получает компактную сводку (`context.js`: месяц по категориям, 12 месяцев,
   счета, цели) и схему базы; если сводки мало — просит до трёх SQL-запросов. Они выполняются **отдельным подключением только для чтения**
   (`sql.js`: один SELECT/WITH, без PRAGMA/ATTACH, ≤ 200 строк), результаты возвращаются ИИ, и он формулирует ответ.
   Для запросов есть представления `v_ops` (операции в рублях с типом расход/доход/перевод) и `v_accounts` (миграция `004`).
4. **Озвучка** — системный голос Windows (бесплатно, без интернета) или голос OpenAI; можно выключить.

Вопросы и ответы хранятся в `assistant_log` (видны после перезапуска, «Очистить историю» — в настройках помощника).
Проверка — `test/assistant-test.js` (тестовый ИИ, фиктивный микрофон Chromium, реальная выгрузка Zenmoney).

## Импорт таблиц квитанций и чеков

`desktop/table-import.js` разбирает CSV, TXT и XLSX без ИИ, `desktop/import.js` добавляет найденное в отчёт.

* **Где:** «Данные → Импорт из файла» (JSON — как раньше, таблицы — здесь), ЖКХ → «Архив квитанций» → «Таблица квитанций»,
  «Питание» → зона «Импорт чека» (таблицы — сразу, фото/PDF/текст чека — ИИ как раньше; TXT без таблицы считается текстом чека).
* **Что понимает:** файлы, выгруженные самим дайджестом; CSV из русского Excel (Windows-1251, «;», «1 234,56»); «Текст Юникод» (UTF-16);
  книги Excel с несколькими листами и ячейками-датами. Заголовки ищутся по смыслу в первых 15 строках, строки «Итого» пропускаются.
  Квитанции: Период, Тип/Поставщик (УК, ЭСК, ЕРЦ ВС), Услуга, Количество/Объём, Тариф, Сумма/Начислено.
  Чеки: Дата, Магазин, Товар/Наименование, Группа, Сумма/Стоимость (или Цена × Кол-во); нет даты или магазина — берутся из формы.
* Перед добавлением показывается, что найдено; совпадающие записи пропускаются, текущие не удаляются. Записи идут в те же наборы `it`/`rcp`
  и в базу (`bill_items`, `receipt_items`). Основной скрипт отчёта публикует для модулей `window.FD_PAGE` (данные и функции перерисовки).
* Проверка — `test/import-test.js`.

## Выводы ИИ по листам (этап 5)

`insights/insights.js` одним запросом к ИИ готовит 2–4 вывода для каждого листа (что изменилось, почему, что проверить)
по сводке помощника и дополнительным срезам: категории за 4 месяца, история капитала, продукты по группам и магазинам, строки квитанций.
Ответ проверяется (тон warn/good/info, длина), хранится в `docs` (`insights/latest`) вместе с отпечатком данных.

* **Когда:** после обновления данных, если они изменились и прошло ≥ 4 ч, и не реже раза в сутки (выключается в «Подключения → ИИ»);
  при запуске — через 20 с, если устарели; вручную — «Обновить выводы» на любом листе.
* **Где:** `desktop/insights.js` — на «Доходах и расходах» выводы заменяют пример в «Разборе последних трёх месяцев»,
  на «Балансе» карточка идёт после ключевых цифр, на остальных листах — первой. Без ИИ или данных карточек нет (пример остаётся).
* Ошибка ИИ не стирает прежние выводы — причина показывается под ними. Проверка — `test/insights-test.js`.

## Регион и имущество (0.9.0)

* `main/insights/region.js` — справочник 89 субъектов РФ; ориентиры региона и РФ (зарплата, норма сбережений, доли трат) запрашиваются
  у ИИ с указанием источника и периода, проверяются на правдоподобие, кешируются в `docs`. Обновляются кнопкой и вместе с выводами ИИ.
  Страница — `desktop/region.js` (prepare-digest, шаг 8.13): выбор субъекта (`settings.app.region`), таблица «Вы, регион и РФ», кривая «Где вы по доходам».
* `desktop/assets.js` — объекты имущества (квартира, дом, машина, участок, гараж, коммерческая, другое): поля и формула оценки по типу,
  цвет карточки по категории, сумма в верхнем блоке «Оценочная стоимость». Хранятся в БД (`docs`).
* Расходы и доходы — как в приложении Zenmoney (`digest/build.js`, BUILD_VERSION 6), одно правило для всех срезов
  (месяц по дням, прошлый месяц, прошлый год, средние, помесячные итоги, категории, сравнение лет): доход в расходной категории —
  возврат, уменьшает расход в день поступления; расход в доходной категории — уменьшение дохода; «Корректировка» и операции без
  категории — расход. Сверено 27.10.2026 по дням октября и по 12 месяцам с отчётом Zenmoney — `test/zen-rules-test.js`.
  Выключатель «без разовых трат от 100 тыс.» убирает такие траты из средних и линий сравнения (`SEP_BIG`, `PY_BIG`).
* Проверка — `test/v09-test.js`.

## Интерфейс: переключатели, панели, анимации

* Все флажки — переключатели (`desktop/controls.css`, рисуются самим полем, `role="switch"`), подпись сразу справа.
* Панели «Помощник», «Подключения», «Данные», меню «⋯» — по одной (`desktop/overlay.js`); тост и окно прогресса уходят от открытой
  панели (`shell.css`, `:has()`). Появление/скрытие — переходы с `display … allow-discrete`; подсказки статуса проявляются при новом тексте.
* «Баланс»: после плашек с цифрами — одна карточка «Выводы ИИ и сигналы дня» (`#fd-sigcard`: выводы ИИ сверху, сигналы по данным ниже);
  «Цели» | «Справка»; «График» (s7) | «Категории» (s5) — пропорция как на «Продуктах» (prepare-digest, шаг 8.8).
  Лист «Питание» переименован в «Продукты» (8.10), «(лист 1)» в пассивном доходе — ссылка «Баланс и цели» (8.11).
* Календарь полей `date`/`month` — `desktop/datepicker.js` (свой скруглённый попап, клавиатура, системный значок скрыт).
* Отклик кнопок (`controls.css`): нажатие — `scale(.96)` 160 мс ease-out, выбор варианта — `fdpick`, наведение только при `hover:hover`;
  точка сигнала мерцает при наведении на строку (`fdblink`); всё отключается при `prefers-reduced-motion`.
* Пустая раскрытая карточка «Добавить ИИ» — кнопка «Убрать» со схлопыванием; при закрытии панели убирается сама.
* Круговые диаграммы — 16 цветов категорий (`--cat1…16`), порядок проверен dataviz/validate_palette.
* Проверка — `test/ui-pass-test.js`.

## Модели ИИ и выпадающие списки

Списки моделей берутся из API провайдера целиком (постранично), с пометкой `chat` — подходит ли модель для текста;
кеш в `settings.ai.modelLists` на сутки (`router.models`), «Проверить и обновить список» — заново. В «Подключениях» список
сгруппирован: «Для отчёта и помощника» и «Другие модели API», есть «Ввести название вручную…». Если выбранной модели нет в API,
подставляется разумная (`pickDefault`: Sonnet, стабильная Flash, gpt-*). Все `<select>` программы оформлены `desktop/controls.css`
(`appearance: base-select`): скруглённое поле и скруглённый раскрывающийся список в цветах темы. Проверка — `test/models-test.js`.

## Обновление программы (0.10.0)

* `main/updates.js` — GitHub Releases: список релизов (`/repos/{o}/{r}/releases`), сравнение версий с pre-release, автопроверка
  (через минуту после запуска и раз в 12 ч, `settings.updates`), скачивание установщика во %TEMP% с проверкой sha512 из
  `latest.yml` и размера, тихая установка `/S --updated --force-run` и выход. Закрытый репозиторий — токен `github_token`
  в secrets.json (запросы к API и ассетам с `Authorization`). Каналы `updates:*`, событие `updates:available` / `updates:progress`.
* `desktop/about.js` — вкладка «О программе» в «Подключениях» и пункт меню «⋯»: создатель, версия, репозиторий, токен,
  переключатели, состояние, прогресс, список версий (установить / откатиться, релиз, исходники), инструкция по выпуску.
* `scripts/release.js` (`npm run release`) — electron-builder `--publish always` в GitHub + архив исходников (`git archive HEAD`).
* Проверка — `test/updates-test.js` (локальная подмена API через `FD_GH_API`).

## Как расширять

* **Новая таблица / поле** — новый файл `db/migrations/00N_*.sql`. Применится сам при запуске.
* **Новый ИИ-провайдер** — файл в `ai/providers/` с `listModels()` и `complete()` + строка в `router.js`.
* **Новый источник данных** — модуль в `connectors/`, каналы в `ipc.js`, раздел в `connections.js`.
* **Правка отчёта** — прямо в `src/renderer/digest/index.html` (или в веб-версии + `npm run prepare-digest`).

```bash
npm install
npm run vendor          # шрифты, pdf.js, xlsx — локально
npm run prepare-digest  # веб-версия → src/renderer/digest/index.html
npm start               # запуск для разработки
npm run dist:win        # dist/FinDigest-Setup-<версия>.exe (на Linux нужен wine + wine32)
```
